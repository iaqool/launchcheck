# LaunchCheck

[English README](README.md) · [Заявка на английском](docs/SUBMISSION.md) · [Развёртывание](docs/DEPLOYMENT.md)

LaunchCheck — инспектор пулов Meteora DBC только для чтения. Он собирает паспорт запуска по данным pool, config, mint, резервам, комиссиям и миграции, показывая путь от торговли на DBC-кривой до подтверждённого пула DAMM v2. Приложение не подключает кошелёк, не подписывает и не отправляет транзакции.

## Локальный запуск

Требуются Node.js 22 и npm.

```powershell
npm ci --ignore-scripts
npm run build
npm start
```

Production-сервер слушает `http://127.0.0.1:4174`. Для разработки запустите `npm run dev` и откройте `http://127.0.0.1:5173`. Vite проксирует `/api` на backend `127.0.0.1:4174`, поэтому для `npm run dev` сохраняйте `PORT=4174`. Не запускайте одновременно `npm run dev` и production `npm start` на этом же порту.

Сервер и smoke-команда читают `.env` из корня проекта через Node `process.loadEnvFile`, если файл существует. Чтобы настроить RPC, скопируйте `.env.example` в `.env` и измените значения:

```powershell
Copy-Item .env.example .env
```

Поддерживаются `SOLANA_MAINNET_RPC_URL`, `SOLANA_DEVNET_RPC_URL` и `PORT`. Если RPC-переменная не задана, используется публичный Solana endpoint. Секреты RPC храните только в переменных окружения сервера; не используйте для них префикс `VITE_`.

## Инспекция и сравнение

Введите адрес DBC pool и выберите Mainnet или Devnet. Успешное чтение из сети помечается **LIVE READ**. Три примера — торговля на кривой, ожидание миграции и созданный DAMM v2 — помечены **SAMPLE DATA** и содержат иллюстративные данные. Ошибка live-чтения не подменяется примером.

Экспортируйте отчёт в JSON, чтобы сохранить снимок. Для сравнения импортируйте прежний отчёт как baseline. Импортированные отчёты — неподписанные пользовательские данные, они не проходят независимую аутентификацию. Сравниваются только отчёты одного пула, сети и источника данных.

MVP поддерживает обычные SPL base-токены с WSOL в качестве quote и целью миграции DAMM v2. Настроенное распределение ликвидности не подтверждает фактическое владение LP NFT после миграции, блокировки позиций или vesting. Наличие ожидаемого аккаунта DAMM v2 подтверждает его существование и совпадение mint-ов, но не текущую торговую активность пула.

## Проверки и smoke-чтение

```powershell
npm test
npm run smoke -- <DBC-pool-address> [mainnet-beta|devnet]
```

Подтверждённый `npm test`: **58 passed, 0 failed**. `npm run build` завершился с кодом **0**. Подробности — в [VERIFICATION.md](VERIFICATION.md).

Smoke-команда выполняет инспекцию только для чтения, проверяет формат отчёта, печатает краткий результат и сохраняет JSON в `artifacts/`. Проверены два mainnet-пула: `51behYte9RzbqGKTz1CxMg6Q79GYhZC44YGeMcUDi7cH` в стадии trading и `2yoLr8GDWacNMbwf88DAiQrxGom59uaP5vXjo9EJ1oCe` в стадии migrated. Для второго подтверждён ожидаемый DAMM v2 аккаунт `DjWLb6eAJ6reUERuaNszD8RSdx2qqwDqdB31ET3DxWeq`. Это чтение существующих аккаунтов, а не выполнение собственной миграции.

На devnet завершён цикл: создание config/pool → DBC buy/sell → достижение порога → миграция → DAMM v2 buy. Все семь транзакций finalized; фактическое поступление токенов после DAMM swap проверено. Цикл выполнен за три прогона с продолжением после сбоев. [Доказательства и ссылки на транзакции](DEVNET-PROOF.md). DBC pool `4KSYjPvfeQghULdKBD7r1T2naxCvLtknr3QET3VcuaGS` теперь мигрировал в DAMM `BWc9k9ggRS1d4KSU9DkokTU16nvYUCH9B7MgMKxVRr5j`. [Инструкция devnet rehearsal](scripts/README-rehearsal.md) описывает повторение проверки и сохранение снимков.

Сначала выполните `npm run devnet:wallet`: команда создаёт кошелёк один раз в локальном `.env.devnet.local`, исключённом из Git, и печатает только публичный адрес. Повторный запуск читает тот же кошелёк. Затем `npm run rehearsal:session` ждёт минимум 0.5 тестовых SOL и выполняет прогон. Заданный извне `DEVNET_KEYPAIR_JSON` имеет приоритет. Без настроенного кошелька запуск останавливается до запроса пополнения. Проверяйте неподтверждённые подписи перед повтором. Старые адреса `EVy3…` и `Ci3s…` потеряли ключи и больше не используются. Для продолжения созданного пустого пула есть `DEVNET_RESUME_POOL` — см. инструкцию. Обычные mainnet SOL не нужны.

## Статус безопасности

`npm start` отключает нативные addons через Node `--no-addons` и проверяет этот запрет до запуска HTTP-сервера. Установка с `--ignore-scripts` и Docker-образ используют JavaScript-путь `bigint-buffer`. Это ограничивает выполнение уязвимого нативного кода; открытый advisory и пять записей аудита сохраняются. Подробнее о запуске демо — [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

После обновления TOML и Jayson аудит сообщает **5 high, 0 moderate, 0 critical** вместо прежних 14 записей. Оставшиеся записи связаны с одной уязвимостью `bigint-buffer`; исправленного релиза нет. На проверенных SPL-путях длина входного буфера фиксирована, но полной безопасности SDK это не доказывает. Подробности и основания overrides — в [SECURITY.md](SECURITY.md). LaunchCheck пока не готов к production. Инспектор показывает только прочитанные данные аккаунтов и ограниченные проверки: это не аудит безопасности токена, не прогноз цены и не оценка безопасности.
