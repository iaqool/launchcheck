# LaunchCheck — ТЗ MVP

Дата: 2026-10-03. Статус: локальный MVP реализован; полный devnet-цикл подтверждён семью finalized-транзакциями за три прогона с продолжением после сбоев. Доказательства — [DEVNET-PROOF.md](DEVNET-PROOF.md). Публичного деплоя и подачи ещё не было. Рабочий дедлайн конкурса: 2026-10-13 11:59 UTC+5.

## Продукт

Инструмент для разработчиков Meteora launchpad: проверяемый паспорт запуска DBC и состояния перехода в DAMM v2. Пользователь вводит адрес DBC pool, получает факты из сети, список ограниченных проверок и следующий шаг миграции. Может сохранить JSON-отчёт и сравнить его с новым чтением того же пула.

Первый пользователь — техническая команда launchpad. Полезность и готовность платить пока гипотезы. Продукт не выдаёт сертификат безопасности и не прогнозирует цену.

## Объём первой работающей версии

1. Веб-приложение на английском, адаптивное, с доступными клавиатурой формами.
2. Ввод адреса DBC pool и выбор mainnet/devnet. Конфиги, mint-адреса и произвольные JSON SDK-конфиги в первой версии не принимаются вместо pool.
3. Реальные чтения через официальные SDK: pool, config, mint decimals, целевой DAMM pool при завершении миграции.
4. Паспорт: адреса, quote reserves / threshold, стадия запуска, параметры комиссий, получатели комиссий и распределение LP.
5. Проверки только того, что подтверждается прочитанными аккаунтами. Неизвестное или неподдерживаемое отображается явно, не превращается в успешную проверку.
6. Следующий шаг миграции по реальному состоянию. Ссылка на официальный manual migrator.
7. Экспорт JSON и сравнение значимых параметров с ранее экспортированным отчётом того же пула/сети. Импорт — пользовательский baseline, не доказательство подписи или одобрения.
8. Три явно помеченных учебных примера: кривая торгуется, переход ожидается, DAMM v2 создан. Ошибка RPC никогда не подменяется примером.
9. Воспроизводимые тесты проверок, точности сумм, ошибок RPC/ввода и сравнения отчётов. Production build и браузерная проверка.
10. Отдельный devnet smoke/rehearsal script. Сохраняет валидированные live-отчёты создания/продолжения пула, достижения порога и миграции для импорта в приложение. Полный цикл до DAMM swap засчитывается только после фактического выполнения с транзакциями. Payer загружается из `DEVNET_KEYPAIR_JSON` или локального `.env.devnet.local`, исключённого из Git; без настроенного кошелька запрос пополнения не начинается. Resume пустого пула и продолжение после двух подтверждённых DBC-сделок проверяют состояние и receipts до новых записей.

## Ограничения

- Mainnet только чтение; приложение не принимает ключи, не подписывает и не отправляет транзакции.
- Первая поддерживаемая семья: обычные SPL base tokens с SOL quote и DAMM v2 target. Остальные случаи возвращают явное unsupported/partial вместо ложного заключения.
- RPC URLs задаются только окружением сервера. Пользователь не может превратить API в произвольный сетевой прокси.
- Денежные целые значения не преобразуются в JS number до форматирования; проценты допустимы как ограниченные производные.
- Снимок нескольких аккаунтов не заявляется атомарным. Сохраняется время/контекст чтения, ограничения видны в отчёте.
- Никаких новых on-chain программ, оплаты, marketplace, AI-советника, собственного keeper и регистрации пользователей в MVP.
- Деплой, платный RPC, mainnet операции, сообщения командам, подача заявок выполняются отдельным шагом после готового результата.

## Архитектура

- React + TypeScript + Vite: один рабочий экран инспекции.
- Node HTTP server: небольшой API и раздача production assets; локальный bind по умолчанию.
- `src/shared/report.ts`: единый JSON-контракт.
- `src/core/`: SDK чтения, нормализация и проверки.
- `src/server/`: валидация входа, ограничения запросов, API.
- `src/ui/`: интерфейс и стили.
- `tests/`: содержательные regression-тесты; `scripts/`: запуск и smoke-проверки.
- Без базы данных; baseline и отчёт хранятся у пользователя.

## Дизайн

Предмет — техническая приёмка запуска. Главный элемент — горизонтальная цепочка DBC → curve complete → DAMM v2, связанная с реальными состояниями. Палитра: ink #16283e, canvas #edf2f7, paper #ffffff, cobalt #285de5, teal #187c70, amber #a96510. Заголовки Bahnschrift, текст Segoe UI, адреса Consolas с системными fallback. Асимметричная рабочая область: ввод и факты слева, проверки справа; без маркетингового hero и фиктивных показателей. Различать live и sample текстом, не только цветом. Проверка плана: обычный crypto dashboard заменён паспортом с источниками и конкретными результатами проверок.

## Исполнение и модели

Оркестратор отвечает за контракт, ограничения, сборку и приёмку. GPT-6-Sol — SDK и domain checks. GPT-6-Luna — UI в ограниченной области файлов. Astra — независимая проверка корректности после интеграции. Изменения агентов разделены по файлам; общий контракт меняет оркестратор. Никаких коммитов/пушей в рамках текущей просьбы.

## Приёмка

- Неверный адрес, чужая программа, отсутствующий аккаунт, неподдерживаемый token/target и недоступный RPC различимы.
- 100% threshold не означает успешную миграцию без существующего DAMM pool.
- Параметры комиссий не выдаются за точный текущий fee при неизвестной dynamic составляющей.
- Сравнение разных pool/cluster отвергается; изменения правил отделены от обычных изменений резервов/стадии.
- JSON не содержит RPC credentials, приватных ключей или BigInt/BN объектов.
- Образцы не смешиваются с live или baseline live; они всегда явно подписаны.
- В отчёте о работе перечисляются реально пройденные проверки и оставшиеся непроверенными пункты.
